本文借用 **System 0 / 1 / 2** 来说明机器人控制中的不同职责。System 1 / 2 沿用了 Daniel Kahneman《思考，快与慢》中广为传播的快慢思考说法，System 0 则见于部分机器人系统对底层运动控制的命名，例如 Figure 的 Helix 02。**这是一种工程类比，并不严格对应人脑结构，也不是机器人领域统一的架构标准。** 各层的具体实现和运行频率取决于系统设计。[Helix 02 官方说明][helix02]

- **System 2：任务理解与规划。** 根据场景、语言指令和执行反馈，选择子任务、安排步骤，并在失败时调整计划。它向下层传递的可以是文字指令、工具调用或潜在表示，具体形式和规划能力因实现而异。
- **System 1：视觉运动策略与技能执行。** 根据视觉、本体感知等观测生成动作或动作序列。[ACT][act]、[Diffusion Policy][diffusion-policy] 以及基于 flow matching 的动作策略可以帮助理解这一层，但这些方法本身不必然构成一个完整的 VLA，也不必然采用独立的快慢双系统。
- **System 0：底层运动控制与稳定执行。** 在具体机器人上跟踪动作目标、协调接触与身体运动。全身控制（WBC）、模型预测控制（MPC）、阻抗控制以及强化学习得到的运动策略，都可能参与这一过程，但它们不必属于同一层，也不必处于同一个控制频率。

这些职责不必一一对应独立的模型。以 Physical Intelligence 提出的 [Hi Robot][hi-robot] 为例，它重点讨论 S2 与 S1 的协作：高层 VLM 根据用户任务、场景和语言反馈生成当前子任务，下层 π₀ VLA 再将子任务转化为机器人动作。

**Hi Robot 的高层 VLM 与下层 π₀ 都以 Google 的 PaliGemma-3B 为 VLM 主干。** 两者从相同的预训练底座出发，分别针对任务决策和动作生成进行微调，训练后的参数独立使用。它们的主要区别体现在输入、输出和训练目标上。[Hi Robot 论文 §4.4][hi-robot-paper]

| 比较项       | 高层 VLM（S2）                  | 下层 π₀ VLA（执行端）                            |
| ------------ | ------------------------------- | ------------------------------------------------ |
| VLM 底座     | PaliGemma-3B                    | PaliGemma-3B                                     |
| 输入         | 图像、用户任务和语言反馈        | 图像、子任务指令、机器人状态                     |
| 输出         | 文字子任务和语言回应            | 连续动作块                                       |
| 训练目标     | 文本的下一 token 预测（交叉熵） | 连续动作生成（flow matching）                    |
| 额外动作模块 | 无需动作专家                    | 新增约 **300M 参数的动作专家**（[π₀ 论文][pi0]） |

Hi Robot 通过自然语言子任务连接高层决策与动作执行。在其他系统中，这种分工也可以通过显式的技能接口实现。

类似架构的差异，可以先从**任务规划与动作执行是否由独立模型承担**来理解。Hi Robot、Galaxea G0 和 Gemini Robotics 都采用“独立规划器 + 动作执行模型”的组织方式：S2 处理用户目标、任务步骤和反馈，S1 执行当前子任务。Hi Robot 与 G0 为高低层设计了不同的训练数据和目标；Gemini 也明确区分 ER 与 VLA 两个模型，但仅凭公开的架构说明，不能推断其完整的联合训练流程。[Hi Robot 论文][hi-robot-paper]、[G0 论文][galaxea-g0]、[Gemini Robotics 2 官方说明][gemini-robotics2]

**π₀.₅ 则把这两种职责放进同一个模型。** 它共用一个 VLM 主干，先生成文字子任务，再通过 flow matching 动作专家生成连续动作块。因此，它不需要额外的独立规划模型，但仍保留了高层决策和低层动作两种输出路径。“统一模型”不意味着所有计算都使用同一套参数，也不意味着规划和动作必须以相同频率更新。[π₀.₅ 官方说明][pi05]

**模型如何划分，与训练时如何耦合，是两个不同的问题。** 初代 Helix 的 S2 与 S1 虽然是不同网络，却通过连续潜变量端到端联合训练；DIAL 也先进行分模块预热，再让动作侧梯度回传到 VLM。它们说明，多模块架构同样可以联合优化，不能简单归入“两个模型各自训练”。Helix 02 新增的 S0 还具有独立的运动跟踪训练过程，也不宜把三层理解为同一个训练目标。[Helix 官方说明][helix]、[DIAL 项目说明][dial]、[Helix 02 官方说明][helix02]

| 架构                                  | 模型组织方式                  | 高层 → 下层                                        | 训练与接口特点                                                                   |
| ------------------------------------- | ----------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------- |
| [Galaxea G0][galaxea-g0]              | 独立规划模型 + 执行模型       | G0-VLM → G0-VLA                                    | 高低层采用不同训练配方，以语言子任务连接，运行时异步协作。                       |
| [Gemini Robotics 2][gemini-robotics2] | 独立规划模型 + 执行模型       | Robotics ER 2 → Robotics 2 VLA                     | ER 负责理解、编排和进度跟踪，VLA 负责执行；完整训练耦合方式需以公开细节为准。    |
| [π₀.₅][pi05]                          | 统一模型中的语义分层          | 同一 VLM 主干生成子任务 → 动作专家                 | 共用主干，分别通过文字 token 和连续动作路径输出高层决策与低层动作。              |
| [Helix 02][helix02]                   | 潜变量连接的多模块层级        | S2 语义潜变量 → S1 关节目标 → S0 运动控制          | 通过连续表示和关节目标衔接；S0 使用运动数据和仿真强化学习训练。                  |
| [GR00T N1.7][groot]                   | 完整 VLA 内的模块分工         | Cosmos-Reason2-2B 表征 → flow-matching DiT 动作头  | VLM 提供条件特征，动作头生成动作块，不等同于外接一个文字子任务规划器。           |
| [DIAL][dial]                          | 端到端耦合的双模块            | VLM 预测未来视觉特征 → 动作策略                    | 先分模块预热，再联合优化，通过预测的未来特征连接语义与动作。                     |
| [τ₀-VLA][tau0-vla]                    | 独立规划体系 + 执行模型的扩展 | 子任务提案、世界模型预测与搜索 → VLA               | 高层包含多个模型，可评估候选子任务的预测结果后再执行，已超出恰好两个模型的划分。 |

从工程取舍看，分模型便于分别迭代规划器和执行器，但要维护两者的接口与能力匹配；统一模型可以共用主干，训练时则需要协调语言与动作目标，运行时仍要安排规划和动作更新的节奏。因此，比较时应同时检查**是否共享主干参数、动作梯度能否回传，以及两层通过什么信息连接**。

## English

This article uses **System 0 / 1 / 2** to describe different responsibilities in robot control. System 1 / 2 borrows the fast-and-slow thinking terminology popularized by Daniel Kahneman's *Thinking, Fast and Slow*. Some robot systems, such as Figure's Helix 02, use System 0 to name a lower motion-control layer. **This is an engineering analogy, rather than a literal mapping of brain structures or a universal robotics standard.** The implementation and operating frequency of each layer depend on the system design. [Helix 02 announcement][helix02]

- **System 2: Task understanding and planning.** Uses scenes, language instructions, and execution feedback to select subtasks, sequence steps, and revise plans after failures. It may communicate with lower layers through text instructions, tool calls, or latent representations; the interface and planning capabilities vary by implementation.
- **System 1: Visuomotor policies and skill execution.** Generates actions or action sequences from vision, proprioception, and other observations. [ACT][act], [Diffusion Policy][diffusion-policy], and policies based on flow matching illustrate relevant approaches, but they do not inherently constitute complete VLAs or separate fast-and-slow systems.
- **System 0: Low-level motion control and stable execution.** Tracks action targets and coordinates contact and body motion on a particular robot. Whole-body control (WBC), model predictive control (MPC), impedance control, and learned motion policies may participate, without necessarily occupying the same layer or running at the same frequency.

These responsibilities do not have to correspond to separate models. [Hi Robot][hi-robot], developed by Physical Intelligence, provides a concrete example of S2–S1 coordination: a high-level VLM generates the current subtask from the user's goal, scene observations, and language feedback, while the low-level π₀ VLA turns that subtask into robot actions.

**Both the high-level VLM and the low-level π₀ use Google's PaliGemma-3B as their VLM backbone.** Starting from the same pretrained base, they are fine-tuned separately for task decisions and action generation, with independent parameters after training. Their main differences lie in their inputs, outputs, and training objectives. [Hi Robot paper §4.4][hi-robot-paper]

| Comparison               | High-level VLM (S2)                            | Low-level π₀ VLA (execution)                                |
| ------------------------ | ---------------------------------------------- | ----------------------------------------------------------- |
| VLM base                 | PaliGemma-3B                                   | PaliGemma-3B                                                |
| Inputs                   | Images, user goals, and language feedback      | Images, subtask instructions, and robot state               |
| Outputs                  | Textual subtasks and verbal responses          | Continuous action chunks                                    |
| Training objective       | Next-token prediction for text (cross-entropy) | Continuous action generation (flow matching)                |
| Additional action module | No action expert required                      | An added **300M-parameter action expert** ([π₀ paper][pi0]) |

Hi Robot connects high-level decisions and action execution through natural-language subtasks. Other systems can implement this division through explicit skill interfaces.

Related architectures can first be compared by **whether task planning and action execution are assigned to separate models**. Hi Robot, Galaxea G0, and Gemini Robotics use a separate planner and execution model: S2 handles user goals, task steps, and feedback, while S1 executes the current subtask. Hi Robot and G0 use different training data and objectives for their two levels. Gemini likewise distinguishes ER and VLA models, although its public architecture description alone does not establish the complete joint-training procedure. [Hi Robot paper][hi-robot-paper], [G0 paper][galaxea-g0], [Gemini Robotics 2 announcement][gemini-robotics2]

**π₀.₅ places both responsibilities within one model.** A shared VLM backbone first predicts a textual subtask, after which a flow-matching action expert generates continuous action chunks. This removes the need for an additional independent planner while retaining distinct high-level and low-level output pathways. A unified model does not require every computation to use the same parameters or planning and action updates to run at the same frequency. [π₀.₅ announcement][pi05]

**Model boundaries and training coupling are separate questions.** Original Helix uses distinct S2 and S1 networks but trains them jointly through a continuous latent interface. DIAL similarly starts with separate-module warmup and then allows action gradients to flow into the VLM. Multiple modules can therefore be jointly optimized rather than necessarily trained independently. Helix 02 also adds S0 with its own motion-tracking training process, so the three layers should not be treated as sharing one training objective. [Helix announcement][helix], [DIAL project][dial], [Helix 02 announcement][helix02]

| Architecture                          | Model organization                       | High level → low level                                       | Training and interface                                                                                                                       |
| ------------------------------------- | ---------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| [Galaxea G0][galaxea-g0]              | Separate planner and executor            | G0-VLM → G0-VLA                                              | Different training recipes, connected by language subtasks and operating asynchronously.                                                     |
| [Gemini Robotics 2][gemini-robotics2] | Separate planner and executor            | Robotics ER 2 → Robotics 2 VLA                               | ER handles understanding, orchestration, and progress tracking; the VLA executes. Full training coupling requires further disclosed details. |
| [π₀.₅][pi05]                          | Semantic hierarchy within one model      | Shared VLM backbone predicts subtasks → action expert        | A shared backbone supports textual-token and continuous-action output pathways.                                                              |
| [Helix 02][helix02]                   | Multiple modules connected by latents    | S2 semantic latents → S1 joint targets → S0 motion control   | Continuous representations and joint targets connect layers; S0 is trained with motion data and simulation reinforcement learning.           |
| [GR00T N1.7][groot]                   | Modular components within a complete VLA | Cosmos-Reason2-2B features → flow-matching DiT action head   | The VLM provides conditioning features and the action head generates chunks; this is not an additional textual subtask planner.              |
| [DIAL][dial]                          | Two modules coupled end-to-end           | VLM predicts future visual features → action policy          | Separate-module warmup precedes joint optimization, with predicted future features connecting semantics and actions.                         |
| [τ₀-VLA][tau0-vla]                    | Extended planning system plus executor   | Subtask proposals, world-model predictions, and search → VLA | Multiple high-level models can evaluate predicted candidate outcomes before execution, extending beyond an exactly two-model split.          |

As an engineering tradeoff, separate models allow planners and executors to evolve independently but require interface and capability alignment. A unified model can share a backbone while requiring coordination of language and action objectives during training and of planning and action updates at runtime. Comparisons should therefore examine **backbone parameter sharing, action-gradient flow, and the information passed between levels**.
